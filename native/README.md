# libquestbridge (native)

C++20 implementation of the Link host as a shared library with a C API, for macOS (arm64) and Windows (x64), plus the `qbhost` CLI. No dependencies except libusb-1.0 on macOS; Windows uses WinUSB directly so adb keeps its interface. Build steps: [docs/building.md](../docs/building.md).

## Layout

- `include/questbridge.h`, two layers:
  - **Session API** for the Unity package (`qb_open`, `qb_poll`, `qb_get_device_info`, `qb_get_head_pose`, `qb_submit_frame_texture`, `qb_get_render_event_func`, …; mirrored in `unity/com.elasticsea.questbridge/Runtime/Native/QuestBridgeNative.cs`). `src/link_runtime.cpp` keeps one process-wide runtime: an I/O thread opens USB when the Quest appears, runs the handshake and reopens after a drop; an encode thread encodes. The runtime outlives every `qb_session`, so the headset session survives Play-mode exits. Unity's per-Play `frame_index` is only used to drop stale or duplicate frames; `frame.index` is session-wide. `qb_session*` is a registry token, so events queued after `qb_close` are ignored.
  - **Host API** (`qb_host_*`): one connection driven by the caller; used by `qbhost` and the tests. Threading rules are in the header.
- `src/`: the protocol core, no I/O: `xrsp` (framing, padding, transfers, reassembly), `capnp` (schema-less codec), `session` (handshake, clock sync, setup pacing, stream seq), `frame` (EncodedSlice patching), `pose` (topic 34), `controllers`, `hands`, `audio`. Transports: `transport_winusb.cpp`, `transport_libusb.cpp`. Texture paths: `texture_encoder_d3d11.cpp`, `texture_encoder_metal.mm`.
- `src/templates_data.cpp`: the recorded PC messages the host builds from, generated by `tools/gen_native_templates.py` from `tests/fixtures/`. The tests fail if it drifts from the fixtures.
- `encoders/`: the H.264/HEVC encoders and `qbenc` ([encoders/README.md](encoders/README.md)).
- `cli/qbhost.cpp`: the CLI, on the C API only.
- `tests/`: byte-exact checks against the fixtures (framing, transfers, Cap'n Proto by allocation order, inner headers, the full handshake replayed through the C API against recorded USB transfers), plus the session API against a fake headset and fake encoder.

## Features

- **Video:** textures are copied inside Unity's render callback. Windows: D3D11 + Media Foundation (`src/texture_encoder_d3d11.cpp`). macOS: Metal render passes split the texture into five IOSurface-backed strips that go straight to the VideoToolbox strip sessions, each strip its own stream with its own parameter sets; under Unity the passes go on Unity's command buffer via `UnityPluginLoad`.
- **Hands:** the host sends InputControl hands-on (topic 28) once streaming (`qb_config.hands`, default 1), and `qb_get_hands` returns 26 OpenXR joints per hand from topic 8 plus the topic 9 bind skeleton.
- **Controllers:** `qb_get_controller` combines the topic 34 controller poses with topic 35 buttons, touches, trigger, grip and stick (flags 0 while the controllers are put down). `qb_haptic` sends a RuntimeIPC call to the headset's haptics service, which the host connects once streaming (`qb_config.haptics`, default 1).
- **Audio:** `qb_submit_audio` queues game audio (resampled to 48 kHz, ≤ 100 ms, 30 ms cushion after running dry); an audio thread sends one 10 ms block on topic 6 every 10 ms while streaming. `qb_read_mic` returns the headset microphone (48 kHz mono int16, newest 1 s).
- **Recovery:** see [docs/protocol/connecting.md](../docs/protocol/connecting.md).

## Environment variables

| Variable | Effect |
|---|---|
| `QB_LOG=1` | Protocol log to stderr |
| `QB_LOG_FILE=<path>` | Log to a file instead (the Unity Editor drops plugin stderr) |
| `QB_GOP` | Frames per intra refresh (default 1 = all intra) |
| `QB_MBPS` | Video bitrate (default 100) |
| `QB_AUDIO=0` | No audio thread |
| `QB_HANDS=0` | Leave hand tracking off |
| `QB_HAPTICS=0` | No haptics connection |
| `QB_USB=0` | Never open USB; sessions stay idle (Unity tests with a headset plugged in) |
| `QB_OVR_STOP=0` | Windows: don't pause Meta's Link service automatically |
| `QB_ENCODER` | Windows: force an encoder backend (see [encoders/README.md](encoders/README.md)) |
| `XRSP_REPLAY=<clip.json>` | `qbhost`: the clip to stream |

## USB

**macOS** (`src/transport_libusb.cpp`): picks a VID `0x2833` device whose interface 0 is class `ff`/`8a` with bulk endpoints `0x01`/`0x81`, claims only that interface (adb keeps its own), one process-wide libusb context. No root and no kernel-driver detach needed (vendor-class interfaces). An unplug shows up as a read or write error; the runtime and `qbhost` then reopen by polling. Why an open failed is logged once per change on the `usb` log line.

**Windows** (`src/transport_winusb.cpp`): opens only the Link interface through WinUSB. When opening fails because Meta's OVRService holds the headset (`src/ovr_service*.cpp`), the library starts one elevated, hidden PowerShell (one UAC prompt per process) that stops the service, waits for this process to exit and starts it again. `qb_stop_ovr_service` asks right away.

## qbhost

```
qbhost --check [--no-claim]          setup check (qb_check_setup); exit 1 if a check failed
qbhost [seconds]                     connect and stream XRSP_REPLAY (or listen without a clip)
```

Wording of the setup check: `src/setup_check.cpp`; platform facts: `src/setup_probe.cpp`.
